# Ангар сборки и 3D-модели модулей

## Как это работает в игре

* На стартовой площадке кнопка **АНГАР (B)** перевозит ракету в здание ангара — оно стоит в 150 м к югу от площадки,
  воротами к ней (видно и снаружи). Ракета на площадке исчезает (физика не меняется: она так и стоит на старте),
  внутри на сборочном стенде появляется 3D-ракета текущего проекта, камера облетает её внутри зала.
* Камера: ПКМ — обзор, колесо — зум, W/S — выше/ниже, A/D — вращать, F — вся ракета, СКМ — сдвиг по высоте.
* Наведение мыши на деталь ракеты — подсказка; клик — выбор (её ступень становится текущей, в каталоге открывается её категория;
  под каталогом появляется блок «НА РАКЕТЕ» с кнопками «Снять», «Показать», «Снять выбор»).

### Меню ангара

| Место | Что там |
|---|---|
| Верхняя полоса | «АНГАР · планета», поле названия проекта, «Новый» (одна пустая ступень и зонд), «Открыть», «Сохранить»; справа «МАГАЗИН (K)», «ВЫВЕЗТИ НА СТАРТ» (применить), «Выйти» (при неприменённых изменениях спрашивает) |
| Рейка слева | 9 значков категорий `ModuleCatalog.Categories` (значки рисуются кодом, `HangarIcons`); подсказка с названием и числом деталей при наведении |
| Панель каталога | поиск по названию и описанию (ищет по всему каталогу); сортировка «Имя / Масса / Цена / Размер», повторный клик меняет направление (▲/▼), без выбора — порядок каталога; подвкладки `SubgroupsOf` («Все» + подгруппы); сетка 3 столбца: миниатюра `ModuleThumbnails.Get` (пока null — значок категории), значок топлива, «×N» — сколько уже стоит на ракете; не купленные затемнены и подписаны ценой |
| Низ панели | блок «НА РАКЕТЕ» (если деталь выбрана на 3D-модели), стоимость проекта (сумма цен), масса на старте, «Ещё купить», бюджет игрока (кредиты профиля) |
| Карточка | при наведении на плитку: название, подгруппа, крупная миниатюра, все значимые числа по типу детали, описание; «После установки: Δv, TWR, масса» и новые замечания — Core компилирует копию проекта с этой деталью; цена, подсказка действия |
| Стек ступеней справа | сверху головной отсек, ниже ступени от верхней к ступени 1 (работает первой): номер, Δv и TWR ступени, значки двигателя (с −/+ числа двигателей), баков и навесного; «! N» — замечания этой ступени; клик — выбрать ступень, × — удалить, «+ Ступень сверху»; внизу суммарный Δv и TWR на старте |
| Панель «Проект / Характеристики / Замечания» | прежние подробные панели (заправка баков ползунком, «Найти», «Убрать», цели миссии, оборудование, замечания); повторный клик по открытой вкладке или ▴ сворачивает её до строки вкладок |
| Под 3D-видом | «Обтекатель», «Вся ракета (F)», строка состояния |

Установка: клик по плитке ставит деталь по её `ModuleMount` — `StageEngine` вместо двигателя выбранной ступени, `StageTank` баком
сверху (заправлен полностью), `StageSide` комплектом на борт выбранной ступени, `Payload` в головной отсек. Плитку можно перетащить:
за курсором полупрозрачный значок с целью («→ ступень 2»), карточка ступени под курсором и сама ступень на 3D-модели подсвечиваются,
деталь ставится при отпускании (на карточку ступени или на деталь ракеты; над пустым залом — на выбранную ступень). Несовместимое
не запрещается: в строке состояния и в карточке показываются новые `BlueprintIssue` / `DesignWarning`. Не купленная деталь по клику
открывает магазин. Цены и покупки меню не меняет.

Именованные проекты хранятся отдельным файлом рядом с профилем: `PlayerSession.SaveDirectory/hangar-projects.json`
(`HangarProjectStore`, атомарная запись, повреждённый файл откладывается как `.corrupt-…`, при профиле только для чтения запись
запрещена). Формат `PlayerProfile` не менялся; летает по-прежнему чертёж профиля, который записывает «Вывезти на старт».
В «Открыть» есть и шаблон «Стандартная ракета» (бывшая кнопка «Сбросить к стандартной»).

* Обтекатель в ангаре снят (иначе приборы не видно) — кнопка «Обтекатель» возвращает его. В полёте он закрывает головной
  отсек, пока работает хоть одна ступень; после отделения последней ступени зонд летит открытым и раскрывает панели.
* Магазин (K) открывается прямо из ангара: купленный модуль можно сразу установить.
* Esc / B / «Выйти»: сначала закрывают открытый диалог проектов; при неприменённых изменениях спрашивают — «Вывезти на старт», «Выйти без изменений» или «Остаться».
* Вёрстка в единицах `HudStyle` (1080p = 1): при 1280×720 экран равен 1707×960 единиц, при 1920×1080 и 2560×1440 — 1920×1080.

Летающая ракета строится тем же кодом, что и ракета в ангаре (`RocketModelBuilder`), поэтому всё, что видно в ангаре,
видно и на площадке, и в полёте.

## Где что лежит в коде

| Что | Файл |
|---|---|
| Раскладка деталей (слоты, размеры, без Unity, с тестами) | `Scripts/Core/Vehicles/RocketLayout.cs`, тесты `Tests/EditMode/Core/RocketLayoutTests.cs` |
| Построение 3D-ракеты: модели из библиотеки или процедурные заготовки | `Scripts/Runtime/Flight/RocketModelBuilder.cs` |
| Библиотека моделей модулей | `Scripts/Runtime/Flight/ModuleVisualLibrary.cs`, ассет `Resources/SpaceSim/ModuleVisualLibrary.asset` |
| Здание ангара, свет, перевод координат | `Scripts/Runtime/Hangar/HangarBuilding.cs` |
| Режим ангара: камера, подсветка, выбор мышью | `Scripts/Runtime/Hangar/HangarFacility.cs` |
| Меню ангара: состояние, вход и выход | `Scripts/Runtime/UI/HangarUI.cs` |
| Части меню (partial-файлы) | `Scripts/Runtime/UI/Hangar/HangarUI.*.cs`: `Edits` (правки проекта, проекты), `Layout` (раскладка экрана, верхняя полоса, диалоги), `Catalog` (рейка, поиск, сортировка, сетка, перетаскивание), `Card` (карточка), `Stages` (стек ступеней), `Details` (сворачиваемые панели), `Format` (форматирование) |
| Значки категорий и топлива | `Scripts/Runtime/UI/Hangar/HangarIcons.cs` |
| Именованные проекты | `Scripts/Runtime/UI/Hangar/HangarProjectStore.cs` |

Физика не читает ничего из этого: масса, тяга, Isp и длины ступеней по-прежнему идут из `ModuleCatalog` через
`BlueprintCompiler`. Высоты ступеней в раскладке равны длинам ступеней, которые компилятор отдаёт физике (это проверяет тест).
Диаметры (сопла, зонд, обтекатель) — только визуальные: сопротивление воздуха считается по радиусу ракеты 1,85 м.

## Как подключить свои 3D-модели модулей

1. Импортируйте модель (FBX/OBJ/glTF-через-пакет) в `Assets/_Project/Models/Modules/` (папку можно создать).
   Единицы — метры. Если модель экспортирована с осью Z вверх — это исправляется полем `rotation` (см. ниже).
2. Меню **SpaceSim ▸ Module Models Library (create or update)** — создаёт/обновляет ассет
   `Assets/_Project/Resources/SpaceSim/ModuleVisualLibrary.asset` с записью для каждого модуля каталога
   (уже назначенные модели сохраняются).
3. В этом ассете найдите запись с нужным `moduleId` и перетащите модель в поле **model**. Всё — в ангаре и в полёте модуль
   теперь рисуется этой моделью. Модули без модели остаются процедурными заготовками.

Поля записи:

* `fit` — как модель вписывается в слот (слот = коробка «диаметр × высота», которую раскладка вычисляет из проекта):
  * `FitInside` — равномерный масштаб, модель целиком помещается в слот (двигатели, приборы);
  * `Stretch` — растяжение по осям точно по слоту (баки, защитные оболочки: их высота задаётся модулем, а диаметр — ракетой);
  * `AsIs` — собственный размер модели × `scale`.
* `rotation` — поворот модели до вписывания (например, X = −90 для моделей с осью Z вверх).
* `offset` — сдвиг после вписывания, м (+Y — вверх по оси ракеты, +Z — наружу от оси).
* `scale` — дополнительный множитель.

Соглашения для моделей (как ориентировать при экспорте):

| Модуль | Слот | Ориентация модели |
|---|---|---|
| Двигатели (`eng-*`) | под баками ступени, по одному на каждый двигатель связки; диаметр — срез сопла | +Y вверх: крепление сверху, сопло вниз; низ модели = срез сопла |
| Баки (`tank-*`) | цилиндр диаметром ракеты (3,7 м), высота = длина бака | ось бака по +Y |
| Зонд (`core-probe`) | центральный корпус головного отсека, 1,8 × 2,5 м | +Y вверх |
| Защита (`prot-*`) | оболочка вокруг зонда, слой за слоем | полый цилиндр по +Y |
| Приборы и пробоотборники (`nav-*`, `sci-*`, `col-*`) | снаружи на корпусе зонда, по кругу | задняя сторона (−Z) прижата к корпусу, лицевая (+Z) смотрит наружу |

Модель самого здания ангара тоже можно заменить: поле `hangarModel` в том же ассете (пивот — центр пола, метры,
+Z — к воротам и площадке). Свет и сборочный стенд остаются.

## Проверка

* `dotnet test Tools/CoreTests/SpaceSim.Core.Tests/SpaceSim.Core.Tests.csproj` — раскладка и физика.
* `dotnet build Tools/UnityStubCheck/UnityStubCheck.csproj` — типы Runtime-кода.
* PlayMode-тест `Hangar_RocketMovesIn_InstalledModulesAppear_ApplyRollsItOut` — вход, установка, вывоз, отмена.
* Мост редактора: `hangar enter`, `hangar add ID [STAGE]`, `hangar view YAW PITCH DIST HEIGHT`, `hangar fairing 0|1`,
  `hangar select ROLE STAGE INDEX`, `hangar apply`, `hangar cancel`, `hangar status`; `modellib` создаёт библиотеку.
